# v1.1.0 — Resource governance

This minor release adds observable resource-governance APIs without changing the
module path or the minimum supported Go version (1.22). The root module still has
no third-party runtime dependencies.

## Added

- `Config.MaxValidationTombstones`: bounded FIFO inactive Raw Slice validation
  history; zero selects 16,384 when validation is enabled. Negative limits and
  non-zero limits with validation disabled are invalid configuration.
- Exact Validation Inventory, independently of optional counters and Pool mode.
- `Stats.Generation` and exact Bounded `ClassInventory`, independent of counters.
- `DroppedUnpooled` (numeric value 8) and its optional counter for valid non-class
  storage within the pooling cutoff. All pre-existing status numbers are unchanged.

## Compatibility boundaries

- Active Raw Slice ownership records are never evicted due to the history limit.
  An old alias whose tombstone is evicted or cleared is rejected as foreign rather
  than duplicate, without modification. Clear preserves active ownership records.
- Valid class-gap disposal changes from `DroppedInvalid` to `DroppedUnpooled`;
  callers switching on statuses should handle the new outcome. Oversize and
  ownership-failure classifications remain distinct.
- Raw Slice validation remains diagnostic, not complete protection against ABA or
  saved mutable aliases. Without validation, provenance cannot always be proved.
- The history count is not a Go heap/RSS budget. Active peaks and Go map allocation
  high-water can exceed it; Clear rebuilds active-only validation state.
- Pool must not be copied after first use. Optional counters are not transactional.
  Fast `Retained` is best-effort acceptance and may disappear immediately with Clear.

The release gate requires the [acceptance audit](../reviews/v1.1-acceptance.md),
independent Standards/Spec review, green integration CI, an immutable SSH-signed
`v1.1.0` tag and a GitHub Release. Existing tags will not be moved.
