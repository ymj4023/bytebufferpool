## Implementation decisions

In the specification's listed order:

1. Integer limit/default: configuration matrix and default inventory test.
2. Disabled-validation incompatibility: configuration matrix rejects rather than ignores.
3. Active records unbounded: active-overflow and combined resource-governance tests.
4. Inactivation and FIFO: release converts an active record; FIFO tests check the oldest is foreign.
5. Address reuse: `TestValidationReacquiredStorageGetsNewFIFOPosition` covers old head/middle/tail, plus active reuse above the limit.
6. Rejection and no mutation: dirty/zero duplicate/foreign tests and combined Clear alias probe.
7. Clear rebuild: new active-only map, FIFO reset, isolated post-GC recovery evidence.
8. Raw post-Clear semantics: valid active records survive; concurrent Release may retain or drop stale under the unchanged best-effort contract.
9. Exact Validation Inventory: fields sampled under `validationMu`; configuration matrix spans modes/counters.
10. Generation: capture the published epoch once; initial/repeated/concurrent Clear tests; no ClearCount.
11. ClassInventory: exported value/slice; every configured class and counters-disabled tests.
12. Class/global reconciliation: one set of class locks; acquire/release/budget/Clear and concurrent tests.
13. ClassStats: retained as a separate optional counter surface with non-transactional documentation.
14. Appended status: literal numeric/name compatibility test and unknown-value formatting.
15. Classification: class-gap vs oversize, changed-capacity vs valid release, and zero-capacity malformed Raw Slice coverage.
16. Acquisition-style/provenance boundary: Lease/Raw matrix and explicit unvalidated foreign class-gap test.
17. Public contract clarifications: Go documentation and equivalent English/Chinese README text.
18. Retained Capacity remains the only Bounded budget: no object-count or heap/RSS promise.
19. No high-water metrics: [deferred proposal](../../.out-of-scope/high-water-metrics.md).
20. No runtime dependencies or background cleanup: root manifest and production-source inspection.
21. Compatible minor release: v1.1.0 notes and final signed-release gate.

## Testing decisions

In the specification's listed order:

1. Exported seam only: all new root tests are external-package tests; no internal hooks.
2. Config/default/custom/invalid/copied config: configuration matrix and `TestResourceGovernanceContractsComposeAcrossConfigurations` mutate the caller's config after New.
3. Small-limit FIFO: eviction and duplicate-no-refresh tests.
4. Active overflow: address-reuse overflow test and four-active/limit-one integration case.
5. Address reuse: head/middle/tail replacement and active-owner protection tests.
6. Clear: active-only test plus integration Generation/history/retained-inventory assertions.
7. Dirty/zero rejection: existing security tests and new FIFO/ownership/integration matrices.
8. Validation Inventory with counters on/off: configuration and combined governance matrices.
9. Default/custom Class Inventory and budget transitions: class inventory tests.
10. Fast unavailability: Generation matrix and integration assertions.
11. Generation across modes/counters/repeated/concurrent Clear: class inventory tests.
12. Status numbers/names/unknowns: literal public status table.
13. Classification precedence: status tests and existing changed-capacity/security tests.
14. Optional new counter: `TestDroppedUnpooledCounterRemainsOptional` and integration matrix.
15. Concurrency/race: root validation and inventory tests; final CI below must execute race.
16. Isolated harness: `benchmarks/cmd/validationmem`, fresh-process samples, logical inventory and independent heap measures.
17. Published evidence metadata: memory report plus integration performance report; exact library revision and benchmark-source fingerprint recorded.
18. Final tests/vet/fuzz/race/contracts/all-benchmark/validation/memory gates: execution record below, not inferred from static review.
